# Frontend

Браузерное приложение DjedAI на React + TypeScript (Vite). Вычисления и данные остаются на Python-backend; интерфейс обращается к нему только через HTTP API и SSE по адресу `/api`.

Вёрстка повторяет макет из [docs/ui-design](../docs/ui-design/README.md): токены, компоненты, экраны и все их состояния.

## Запуск

Нужны Node и npm из [.nvmrc](../.nvmrc) и `engines` в [package.json](package.json) — те же версии, что в CI. С fnm или nvm версия подхватывается из `.nvmrc`:

```sh
fnm use            # или: nvm use
cd frontend
npm ci
npm run dev        # http://localhost:5173
```

По умолчанию dev обращается к настоящему backend через `/api`. Для CP1 backend запускается с `CP1_LOCAL_MODE=true`: это локальный режим с одним владельцем данных; экран входа ещё не подключён к аутентификации. Рабочий путь: несколько CSV → прогресс обработки → выбор датасета/каталог → новый или сохранённый чат → текстовый ответ по POST SSE → сохранённые метаданные и строки результата.

Демонстрационный mock-API (MSW) включается только явно через `VITE_API_MOCKS=true` в `.env.local`. Сценарий выбирается параметром адреса и сохраняется для вкладки:

| Параметр | Что показывает |
|---|---|
| `?mock=normal` | обычные данные (по умолчанию) |
| `?mock=empty` | нет датасетов и дашбордов — пустые состояния |
| `?mock=slow` | запросы не завершаются — состояния ожидания |
| `?mock=error` | ошибка профилирования, сбой одного виджета дашборда, ошибка разбора CSV при загрузке |

Vite проксирует `/api` на `http://localhost:8000`; другой адрес задаётся переменной окружения при запуске: `DJEDAI_API_PROXY=http://host:8000 npm run dev` (из `.env.local` она не читается — это настройка самого dev-сервера). В production-сборку моки не попадают.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с proxy к backend; MSW только по явному флагу |
| `npm run typecheck` | строгая проверка типов (`tsc -b`) |
| `npm run lint` | ESLint с проверками типов, без предупреждений |
| `npm test` | тесты Vitest |
| `npm run test:coverage` | тесты с покрытием; ниже 80% строк — ошибка |
| `npm run test:e2e` | production UI + настоящий backend с управляемым HTTP API модели; два датасета и перезапуск |
| `npm run test:e2e:auth` | auth API и общий браузерный клиент: JSON, multipart, GET/POST SSE, reload, перезапуск и истечение |
| `npm run smoke:cp1 -- --url http://localhost:8080 --output /absolute/evidence/path` | браузерная приёмка запущенного приложения с настоящей моделью; повтор с `--verify` после перезапуска |
| `npm run build` | production-сборка в `dist/` |
| `npm run preview` | раздача собранного `dist/` |
| `npm run gen:types` | TS-типы из `schema/openapi.yaml` в `src/api/generated.ts` |

CI выполняет то же самое после `npm ci` и дополнительно проверяет, что `src/api/generated.ts` совпадает с результатом `gen:types`.

Для браузерных проверок один раз установите Chromium: `npx playwright install chromium`
(в Linux CI — `npx playwright install --with-deps chromium`). `test:e2e` самостоятельно
поднимает изолированную SQLite/DuckDB, backend и OpenAI-совместимый управляемый
сервер модели на портах 18080/18081; production UI раздаётся через Vite preview
на 4173 с proxy `/api`. Внешняя сеть и настоящий ключ модели тесту не нужны.
Nginx/Compose и выбранный реальный API проверяются отдельным smoke на общей сборке.
`smoke:cp1` сохраняет SQL, результат, SSE, независимые эталоны CSV и скриншоты
в указанном внешнем каталоге; для `--verify` укажите тот же `--output`.

## Устройство

```text
schema/openapi.yaml   согласованный снимок API (источник TS-типов)
src/
  api/                клиент, SSE, хуки запросов (TanStack Query), преобразование ответов для экранов
  app/                маршруты, каркас (TopBar + Sidebar), общее состояние
  pages/              экраны: вход, источники, каталог, чат, дашборды, 404
  components/         общие компоненты из макета
  charts/             ECharts по ChartSpec и данным результата
  mocks/              mock-API на MSW: данные и обработчики, общие для dev и тестов
  lib/                форматирование (ru-RU), тема, медиазапросы
  styles/             токены макета и подключение Tailwind
  fixtures/           статичные данные компонентов для тестов; рабочий чат их не использует
  test/               настройка тестов и тестовый сервер
```

### API и типы

[schema/openapi.yaml](schema/openapi.yaml) описывает API-фикстуры экранов и ссылается на [schema/contracts.json](schema/contracts.json) для общих моделей каталога, результата, графика, блоков ответа, дашборда/рецепта, пользователя, ошибок и SSE. Этот файл воспроизводимо экспортируется из актуальных Pydantic/OpenAPI-контрактов backend; ручные копии этих моделей не ведутся. Согласованные wire-форматы описаны в [PL-1 / #47](../docs/decisions/47-contracts-and-runtime.md); реализация ещё отсутствующих обработчиков остаётся в #94/#97.

Обновление общих контрактов из корня репозитория и генерация TS-типов:

```sh
uv run --locked python scripts/export_frontend_contracts.py
cd frontend
npm run gen:types
```

Python CI проверяет актуальность `contracts.json`, frontend CI — результат генерации TS. Параметр `--default-non-nullable false` сохраняет необязательность полей с Pydantic-default, включая nullable-поля дескрипторов колонок.

- `src/api/client.ts` — базовый адрес из `VITE_API_BASE_URL` (по умолчанию `/api`), любые ошибки превращаются в `ApiError` с `message` и `suggestion`.
- `src/api/auth.ts`, `session.ts` — Bearer API и токен в памяти/sessionStorage вкладки, общий для JSON, multipart и SSE. Очистка/смена токена отменяет старые запросы; 401 очищает текущую сессию. Формы и очистка workspace/QueryClient подключаются в #104. Подробнее — [AUTH-2](../docs/decisions/102-auth-api.md).
- `src/api/sse.ts` — SSE через `fetch`, в том числе для POST. Разбитые на чанки события собираются, `done`/`error` закрывают поток, отмена через `AbortSignal`. Обрыв без `done` даёт ошибку `stream_interrupted`; запрос никогда не повторяется автоматически, чтобы не запустить агента второй раз.
- `src/api/queries.ts` — хуки по разделам и ключи кэша; `src/api/view.ts` — форматирование ответов для компонентов.
- `src/api/useChatConversation.ts` — создание чата, отправка текста, текущие блоки и восстановление истории через GET. После `done` сохранённая история заменяет текущий ответ целиком. Остановка, смена чата/датасета и уход со страницы отменяют поток. Ошибка/разрыв показывается пользователю; повторный POST возможен только новой отправкой.
- `src/components/SavedResult.tsx` — provenance из `result_ids` сохранённого сообщения, общий GET метаданных и GET `/data`, просмотр SQL/параметров и первых 20 строк. Ссылки JSON ведут на тот же сохранённый результат и работают после перезапуска backend.

Кнопка «Скрыть прогресс» закрывает подписку на события; уже принятая обработка CSV продолжается на сервере. В строке обрабатываемого датасета можно снова открыть прогресс. Список автоматически обновляется, пока есть обработка.

### Как подключить новый запрос к экрану

1. Общий контракт изменить в Python `contracts/`, обновить экспорт; предложение нового пути добавить в `schema/openapi.yaml`, затем выполнить `npm run gen:types`.
2. Добавить хук в `src/api/queries.ts`, при необходимости — преобразование в `src/api/view.ts`.
3. Добавить обработчик в `src/mocks/handlers.ts` (и данные в `src/mocks/db.ts`), чтобы экран работал в dev и тестах.
4. На экране показать `LoadingState` / `EmptyState` / `ErrorState` по статусу запроса — они одинаковы на всех экранах.
5. Тест: страница через `renderRoute()` из `src/test/renderRoute.tsx`, сценарии — `useScenario()` или `server.use()`.

## Зависимости

npm, только точные версии без диапазонов (`.npmrc`: `save-exact=true`, `engine-strict=true`), `package-lock.json` в Git. Новую зависимость добавляем через `npm install <пакет>@<версия>`; проверка репозитория в CI отклоняет диапазоны и рассинхронизацию lock-файла.

## Что делают другие задачи

- Полный интерактивный renderer блоков ответа, уточнения/подсказки, действия графиков и сохранение на дашборд — B4-4 (#86). CP1 подключает реальную отправку/историю/SSE, текст и provenance; базовые ссылки на графики/таблицы читаются через общие контракты.
- Подключения PostgreSQL/ClickHouse и полный UX источников — #84; CP1 принимает CSV. Форма подключения остаётся макетом и получает ошибку «не реализовано» от CP1 backend.
- Рендер всех типов `ChartSpec` — B4-5; сейчас поддержаны line, area, bar и pie.
- Авторизация — своя задача; экран входа сверстан, но не отправляет запросов.
- Раздача `dist/` и `/api` в Compose — #99: nginx должен отдавать `index.html` на любые пути приложения (`try_files $uri /index.html`), чтобы прямой URL и обновление вложенного маршрута работали.
