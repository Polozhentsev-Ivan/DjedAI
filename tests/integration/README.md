# Интеграционные тесты

Проверки реального взаимодействия: DuckDB, адаптеры БД, миграции, API, хранилище, SSE и совместимость контрактов.

Используем отдельные тестовые данные и БД. Для запуска описываем сервисы и конфигурацию; тесты помечаем `integration`, а требующие реальной модели — дополнительно `llm`.

```sh
uv run --locked pytest --strict-markers tests/integration/test_analytics_tools_runtime.py
```

Это отдельный обязательный шаг Python CI для всех зарегистрированных инструментов:
реальные авторизация, CSV, граф, SQL и сохранение с управляемым планом модели.
Внешние сервисы и ключ модели не нужны. Матрица доступа, проверки чувствительности
и порядок добавления инструмента описаны в [аналитических инструментах](../../docs/developer/analytics.md#защищённый-runtime-gate--171).

`uv run --locked pytest --strict-markers tests/integration/test_auth_migrations.py`
проверяет миграции AUTH-1 на временной SQLite: ограничения пользователей/сессий,
сохранность существующих владельцев, откат AUTH и восстановление сессии и ресурсов
из нового Python-процесса. Внешние сервисы не нужны; этот файл запускается в CI.

`DJEDAI_TEST_PG_DSN=postgresql://djedai_reader:…@127.0.0.1:5432/djedai_demo uv run --locked pytest --strict-markers tests/integration/test_postgres_adapter.py`
проверяет адаптер PostgreSQL (B1-8) на демо-БД из [infra/postgres](../../infra/postgres/README.md):
каталог выбранных таблиц через общий профайлер, контрольный запрос против PostgreSQL,
отказ записи, ошибки подключения без пароля и сборка `DatasetCatalog` через
`connect_postgres_dataset` без копирования данных. С `DJEDAI_DEMO_PG_LOADER_DSN` ещё
проверяется профиль таблицы, которую меняет внешний writer: после создания представления
и посреди профилирования (один снимок).
Без переменной тесты пропускаются.
