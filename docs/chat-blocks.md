# Блоки ответа в чате (#86)

Чат показывает ответ ассистента постепенно, по одному блоку `block` из POST SSE
`/chats/{id}/messages`. Типы блоков берутся из общего контракта `MessageBlock`
(`src/djedai/contracts/message.py` → `frontend/src/api/generated.ts`). Рендер
находится в `frontend/src/components/ChatBlocks.tsx`.

| Блок | Отображение |
|---|---|
| `text` | Подмножество Markdown: абзацы, переносы, списки `-`/`1.`, заголовки `#`, `**жирный**`, `*курсив*`, `` `код` ``. Текст выводится только как React-узлы, HTML не исполняется. |
| `chart` | `ChartAnswer`: `ChartCard` + `ResultChart`, данные читаются по `chart.result_id`, все типы описаны в [рендерере графиков](chart-renderer.md). Под графиком — «Как посчитано», в заголовке — «В дашборд» ([#88](decisions/88-how-calculated-save-to-dashboard.md)). |
| `table` | Строки сохранённого результата по `result_id`; учитываются `columns` (пусто — все колонки) и `limit` (по умолчанию 20) и показывается заметка об обрезке. ISO-даты выводятся как `дд.мм.гггг`. У timestamp-колонки сохраняется время в точности, которую несёт хотя бы одно её значение (минуты, секунды, доли секунды); если все значения в полночь, показывается только дата. Время не переводится в пояс браузера, а смещение подписывается (`UTC`, `+03:00`). |
| `clarification` | Вопрос и кнопки вариантов. Клик отправляет текст варианта как следующий вопрос. |
| `suggestions` | Кнопки-подсказки следующего вопроса, поведение такое же, как у уточнения. |
| `dashboard_link` | Карточка-ссылка `/dashboards/{dashboard_id}`. Работающий экран дашборда подключается в B4-7. |
| неизвестный тип или блок с битыми полями | Понятное состояние «Этот тип ответа пока не поддерживается» с именем блока. Остальная часть ответа показывается полностью. |

Под ответом каждый сохранённый результат, включая показанный таблицей, имеет одну
панель «Результат расчёта» с SQL, параметрами и ссылками на JSON. У графика та же
информация открывается прямо под ним кнопкой «Как посчитано».

Кнопки уточнений и подсказок активны только у последнего ответа в чате и только
когда поток не идёт. Варианты старого уточнения остаются видны, но устаревший
вопрос по ним отправить нельзя. Каждый клик выполняет ровно один POST, повтора нет.

Узел агента `clarify` передаёт вопрос и варианты отдельно (`Block.markdown` и
`Block.options`). Сервис чата превращает их в `ClarificationBlock`, если вариантов
не меньше двух и они различны; иначе отправляет обычный текст.

Жизненный цикл потока (статусы, `done`, `error`, отмена, смена чата, выход и
отсутствие автоматического повтора POST) описан в [chat-turns.md](chat-turns.md).
Пока сохранённая история не содержит ответ, блоки, полученные по SSE, показываются
локально. После `done` их заменяет сохранённый ответ, и ни один блок не
дублируется.

## Проверка

Эталонные блоки и события лежат в `tests/fixtures/chat/blocks.json`; этот файл
используют и backend-тесты, и фронтенд (`frontend/src/test/chatFixture.ts`).

- `frontend/src/pages/ChatPage.test.tsx`, раздел «chat answer blocks»:
  - поток фикстуры по одному блоку и затем `done` без дублей;
  - сетевые чанки, разрезанные внутри события, UTF-8 и CRLF;
  - клики по уточнению и подсказке;
  - неизвестный и битый блок;
  - `columns`/`limit` таблицы.
- `frontend/src/pages/ChatPage.test.tsx`, раздел «saving an answer chart to a
  dashboard», и `frontend/e2e/dashboard-save.spec.ts` проверяют «Как посчитано»
  и «В дашборд» (см. [#88](decisions/88-how-calculated-save-to-dashboard.md)).
- `frontend/e2e/chat-blocks.spec.ts` использует production-сборку и управляемые
  HTTP-ответы, модель не нужна. POST `/messages` отдаёт поток, который тест
  подаёт по одному событию, так что виден настоящий постепенный рендер. Проверяются
  статус → блоки → `done`, клик по уточнению, ошибка потока, обрыв без повторного
  POST, незнакомый блок и переход по фикстуре `dashboard_link`.

Из `frontend/`:

```sh
npm test -- src/pages/ChatPage.test.tsx
npm run test:e2e -- chat-blocks.spec.ts
```

Скриншоты (`chat-streaming-status`, `chat-all-blocks-light`/`-dark`,
`chat-unknown-block`, `chat-stream-error`) сохраняются в Playwright output
(`DJEDAI_E2E_OUTPUT`).
