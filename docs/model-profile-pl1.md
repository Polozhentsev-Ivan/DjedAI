# PL-1: профиль модели и реальные замеры

Дата: **20 октября 2026 года**. Решение: **DeepInfra / Qwen3.6-35B-A3B**.
Пользователь разрешил внешний инференс с открытыми весами до 80B суммарных
параметров. У выбранных [официальных весов](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)
35B параметров, 3B активных и лицензия Apache-2.0. DeepInfra указывает
[FP8 и контекст 262 144 токена](https://deepinfra.com/Qwen/Qwen3.6-35B-A3B).
235B-модель предыдущего smoke-прогона исключена из нового профиля.

## Конфигурация

| Параметр | Значение |
| --- | --- |
| Endpoint | `https://api.deepinfra.com/v1/openai` |
| MODEL_NAME | `Qwen/Qwen3.6-35B-A3B` |
| Ответ | strict JSON Schema, temperature=0.1, max_tokens=2048 |
| Thinking | Default провайдера, отдельный переключатель не передаётся |
| Timeout | 60 с на попытку; до двух SDK-повторов транспортных ошибок |
| Контекст приложения | Бюджет 8192 токена, включая резерв ответа 2048; сокращение входа/истории относится к #77 |
| Серверные веса/runtime | Стабильный API ID; SHA обслуживаемых весов, сборка runtime и GPU/VRAM провайдером не раскрыты |
| Локальное оборудование | RTX 4070 Laptop, 8188 MiB VRAM; веса локально не размещались |
| Среда клиента | Windows, Python 3.13.16, зависимости `uv.lock` |

Это управляемый профиль, а не воспроизводимая локальная сборка весов. Для смены
ID или провайдера повторяются описанные ниже замеры. Полное окно 262 144 не
проверялось; успешная контекстная проба содержала **3964 входных токена** по
usage API. Бюджет 8192 — решение для реализации памяти, не заявление о
проверке каждого размера входа до этой границы.

## Метод

[benchmark_model_profiles.py](../scripts/benchmark_model_profiles.py) отправляет
по три повтора шести запросов: классификация численного вопроса, неоднозначные
gross/net продажи, SQL COUNT, SQL SUM по регионам, текстовое число и ответ без
данных. Затем идёт контекстная проба с 200 фиктивными таблицами. Данные полностью
искусственные: `orders = [(A,10), (A,20), (B,5)]`.

Валидность JSON проверяется Pydantic-моделями Understanding/PlanResponse/ComposeResponse.
SQL реально исполняется через штатный реестр инструментов в отдельной DuckDB;
результаты сравниваются с `[[3]]` и `[[A,30],[B,5]]`. Для неоднозначности нужны
`intent=ambiguous` и непустой объект clarification; простая валидность JSON за
правильный ответ не засчитывается. Ошибки инструмента и неисполняемые планы
не обрывают серию. Время — до получения/валидации ответа, включая SDK-повторы;
p95 считается ближайшим верхним порядковым значением, без интерполяции.

```sh
uv run --locked python scripts/benchmark_model_profiles.py \
  --model Qwen/Qwen3.6-35B-A3B --repeats 3 --context-lines 200 \
  --timeout 60 --max-output-tokens 2048
```

Ключ читается из окружения или `.env` (`DEEPINFRA_API_KEY`, иначе `MODEL_API_KEY`).
Команда сохраняет JSON в локальный `artifacts/model-profiles/`; ключ и реальные
данные в отчёт не попадают. Проверки CLI и оценщика работают без внешнего API.

## Результаты финальной серии

Начало серии: `2026-10-20T15:08:29Z`. Локальный отчёт:
`artifacts/model-profiles/pl1-final-20261020.json`.

| Проверка | Валидная схема | Корректный смысл/SQL | Время трёх повторов, с |
| --- | --- | --- | --- |
| Understand: COUNT | 3/3 | 3/3 | 6.202; 5.428; 25.641 |
| Understand: неоднозначность | 3/3 | 1/3 | 9.512; 9.200; 7.375 |
| Plan: COUNT | 3/3 | 3/3 | 7.074; 27.829; 21.291 |
| Plan: SUM по регионам | 3/3 | 3/3 | 17.700; 18.795; 21.855 |
| Compose: число | 3/3 | 3/3 | 18.940; 19.870; 19.663 |
| Compose: нет данных | 3/3 | 3/3 | 21.153; 15.888; 21.294 |
| Контекстная проба | 1/1 | 1/1 | 33.480 |

Итого **19/19 валидных схем (100%)**, **17/19 корректных ответов (89,5%)**.
Медиана **18,940 с**, p95 и максимум **33,480 с**. Фактические значения с
точностью до миллисекунд сохраняются в JSON; округлённая таблица служит протоколом.
Все шесть SQL-планов дали правильные результаты. В двух неоднозначных ответах
модель вернула `intent=ambiguous, clarification=null`: это **ошибка смысла**,
хотя текущая схема её допускает. Серия не доказывает корректность всех маршрутов
и уточнений. Этот случай нужен в полном eval #81 и проверках поведения агента;
выбор профиля не снимает требований к обработке неполных ответов модели.

## Предварительное сравнение и ограничения

Первая серия (`2026-10-20T14:21:07Z`,
`artifacts/model-profiles/pl1-20261020.json`) использовала более краткую инструкцию
к intent и 1500 таблиц в контекстной пробе:

| Модель | Схема | Смысл/SQL | Медиана, с | p95/максимум, с |
| --- | --- | --- | --- | --- |
| Qwen3-32B | 18/19 | 18/19 | 15,776 | 77,069 |
| Qwen3.6-35B-A3B | 18/19 | 16/19 | 9,036 | 59,603 |

У обеих большая контекстная проба завершилась транспортной ошибкой API.
Дополнительный запрос с 400 таблицами получил ReadTimeout около 60 с;
малые пробы с 50 и 200 таблицами прошли. Причина на стороне сети/endpoint
не локализована, поэтому большой контекст не считается подтверждённым.
В финальной серии инструкция явно отличает численный вопрос от общего обзора,
а проба ограничена 200 таблицами; сравнивать две серии как неизменный benchmark
или обещать скорость по одному прогону нельзя. Задержки управляемого API меняются.

35B-профиль выбран как разрешённый по размеру, с валидным JSON и реальным
сквозным SQL-прогоном. Доля невалидных схем в финальной серии ниже порога 20%
из PL-1. Это минимальная проверка выбора, а не полный eval и не SLA 30 с на ход:
лимит 30 с относится к одному инструменту, вызовы модели имеют отдельный timeout.

## Сквозная проверка 500 000 строк

После выбора выполнен [повтор CP1 smoke](cp1-smoke-run.md#повтор-на-модели-до-80b)
с лимитом генерации 2048 и timeout 60. COUNT всей таблицы, независимый CSV-парсер
и текст ответа дали 500000. SQLite, Parquet и DuckDB прочитаны новым процессом.
Прогон подтверждает минимальный путь без UI; issue #106 остаётся открытой.
