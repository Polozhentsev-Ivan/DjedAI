# #159: проверка reasoning-профилей, версия отчёта 2

Дата: 26.10.2026. Рабочий профиль остаётся `provider_default` на всех стадиях.

## Поддержанный контракт измерителя

Это ограниченный синтетический эксперимент стадий и полного графа на четырёх
заказах. Он не заменяет golden eval, защищённый HTTP/runtime/storage набор
#171 или детерминированный контракт произвольных утверждений #167.

- Числа в тексте сверяются с независимыми ожиданиями. Для валют/категорий
  проверяются пары `метка: значение` или `значение метка`, включая десятичную
  запись. Метки RUB/USD, A/B/C и retail/wholesale не переставляются; числовые
  утверждения вне этих пар не засчитываются. Неподдержанная формулировка
  отклоняется, а не получает фиктивное доказательство. Пустой текст не означает
  корректного сообщения об отсутствии данных. COUNT-вопрос больше не содержит
  правильный ответ в своей формулировке.
- Understand проверяет intent, выбранную таблицу/допустимые поля и отсутствие
  выдуманных ссылок. В неоднозначном вопросе варианты должны различать gross/net;
  допустимы имена каталога и русские «валовые/чистые продажи».
- График ссылается на существующий ToolResult; поля, тип графика и отображаемые
  пары категория/величина проверяются по данным результата. Правильный график
  не обязан перечислять все свои числа в текстовом блоке. Если текст содержит
  числовые утверждения, они тоже проверяются.
- Порядок строк строгий только для вопросов с явной сортировкой. В остальных
  случаях сравниваются мультимножества целых строк, с сохранением кратности
  и связи категории со значением.
- Gate сравнивает число успехов и повторов каждого случая. Падение с 2/3 до
  0/3 не компенсируется улучшением другого случая; пропущенный случай или
  различное число повторов не дают `safe_to_enable=true`. Исходные ошибки
  baseline показываются отдельно. Это консервативное правило приёмки малой
  выборки, не статистический тест значимости. `recommendation` согласован с gate.

## Расход и воспроизводимость

Известные usage и finish_reason сохраняются также при OUTPUT_LIMIT,
INVALID_JSON и SCHEMA_MISMATCH. Для неполного usage полный итог равен null,
а известная частичная сумма и количество пропусков указаны отдельно.
HTTP-ошибка стадии сохраняет числовой статус без заголовков/ключа или raw
сообщения провайдера. Невалидный вывод модели сохраняется как данные только
в этом синтетическом benchmark-отчёте; content-free диагностика приложения
не начинает записывать prompts/responses.

Отчёт версии 2 содержит SHA, признак dirty, хеши исходников/prompts/lock-файла
и синтетической фикстуры, явные настройки и полные SQL/ToolResult/answer_blocks/
ChartSpec для каждого хода. Общий deadline графа по умолчанию 120 с; его можно
задать `--turn-timeout`. Отчёт атомарно обновляется после каждого случая;
running/interrupted/failed не выдаются за completed. При прерывании остаются
уже полученные результаты и не публикуется незавершённое сравнение.

```sh
uv run --locked python scripts/benchmark_model_profiles.py \
  --model Qwen/Qwen3.6-35B-A3B \
  --base-url https://api.deepinfra.com/v1/openai \
  --env-file .env.deepinfra \
  --reasoning-profile baseline --reasoning-profile proposed \
  --reasoning-supported --repeats 3 --turn-repeats 3 --context-lines 200 \
  --timeout 60 --turn-timeout 120 --max-output-tokens 2048 \
  --output ../artifacts/model-profiles/checker-v2.json
```

Пример пути к отчёту находится вне репозитория; env-файл с ключом не коммитится.
Smoke-скрипт читает тот же профиль из выбранного env-файла и передаёт его
реальному SDK. Интеграционная проверка перехватывает HTTP-запросы: none у
understand, параметр отсутствует у остальных стадий. Это управляемый endpoint,
без запуска локальной LLM.

Исторические результаты checker v1 в [PL-1](../model-profile-pl1.md) сохранены
с явными оговорками. Они не пересчитываются задним числом по отсутствующим
трассам и не заменяют повтор на версии 2. Три повтора этой серии не закрывают
отдельный объём измерений #162 с минимум пятью повторами на сценарий/профиль.
