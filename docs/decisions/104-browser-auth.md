# Вход и личное пространство в браузере — AUTH-4 / #104

При открытии `/sources`, каталога, чата или дашборда без сессии UI переходит на
`/login`. После reload сохранённый токен сначала проверяется через `/api/auth/me`:
личные запросы и workspace монтируются только после подтверждения пользователя.
При сетевой ошибке проверки можно повторить её, не теряя действующий токен.

Формы `/register` и `/login` используют общий типизированный клиент. Регистрация
создаёт аккаунт, затем клиент явно выполняет login; API регистрации само сессию
не выдаёт. Идентификатор — username, email не используется для входа. Имя и пароль
не нормализуются; пределы формы соответствуют API: username 3–50, password 6–1024.
Ошибки входа, занятое имя, сетевой сбой и ограничение попыток показаны в форме.
Повторная отправка блокируется до завершения запроса; уход со страницы отменяет
ожидающий запрос, пароль после ошибки очищается. Шапка показывает username из me().

Токен остаётся в памяти и `sessionStorage` вкладки. При изменении сессии:

1. Общий AbortSignal закрывает старые JSON/multipart-запросы и GET/POST SSE.
2. QueryClient отменяет запросы и очищает весь кэш, включая результаты и дашборды.
3. Удаляется сохранённый выбор датасета; приватный React-workspace размонтируется.
4. Новый workspace появляется после me() новой сессии; запоздалые ответы старой
   сессии не принимаются общим клиентом.

HTTP 401/403 приватных запросов и terminal SSE unauthorized/forbidden очищают
только соответствующую текущую сессию, показывают страницу входа и объяснение.
403 здесь консервативно требует повторного входа. Ошибки публичных register/login
не считаются истечением сессии. Запоздалый отказ старого запроса не сбрасывает
новый вход. Backend возвращает 404 для чужих ресурсов — это не выход из аккаунта.

Выход сразу закрывает локальное личное пространство и отдельно отправляет
`POST /api/auth/logout` с прежним Bearer. Запрос отзыва имеет собственный timeout
10 секунд и переживает отмену старых потоков. Ни успех, ни запоздалая ошибка logout
не затрагивают новый login. При сетевом сбое локальные данные всё равно очищены;
отзыв на недоступном сервере не гарантируется, серверная сессия имеет прежний TTL.

Личные списки CSV, каталог, чаты и результаты обеспечиваются AUTH-3. Существующий
экран дашбордов находится под тем же guard и использует общий клиент/кэш. Проверка
полного личного списка дашбордов выполняется с реализацией dashboard API (#97).
Итоговая приёмка всех функций двух пользователей остаётся в #105.

## Проверки

- `npm run test:coverage`: формы, проверка восстановленного токена, 401/403,
  смена аккаунта, очистка кэша/выбора, блокировка дубля и поздний ответ.
- `npm run test:e2e`: настоящий backend с миграциями и production UI; регистрация
  двух пользователей формами в одной вкладке, личный CSV, выход во время SSE,
  проверка отзыва токена, reload и возвращение первого пользователя к своим данным.
- `npm run test:e2e:auth`: регрессия JSON, multipart и GET/POST SSE общего клиента.

Ручной запуск: `docker compose up --build -d --wait`, открыть
`http://127.0.0.1:8080/register`, создать аккаунт и загрузить CSV. После выхода
другой аккаунт видит собственный список. Новый аккаунт не получает данные старого
CP1-владельца или других пользователей.
