# Конфигурация

DjedAI получает серверные настройки из окружения процесса и локального `.env`. Образец — [`.env.example`](../.env.example); реальные ключи и строки подключений хранятся вне Git. Для первого запуска достаточно скопировать образец и настроить модель по [инструкции сборки](local-build.md).

Эта глава описывает действующую конфигурацию приложения. Поля и проверки определены в [`backend/config.py`](../src/djedai/backend/config.py), общие лимиты — в [`config.py`](../src/djedai/config.py), выбор модели — в [`agent/config.py`](../src/djedai/agent/config.py) и [`backend/model_settings.py`](../src/djedai/backend/model_settings.py).

## Откуда берутся значения

Окружение процесса имеет приоритет над `.env`. Для полей `Settings`/`LimitSettings` пустая строка означает значение по умолчанию. Неверные числа, NaN, бесконечность и нарушение связанных ограничений отклоняются при загрузке конфигурации. Модельный клиент отдельно читает `MODEL_BASE_URL`, `MODEL_NAME`, `MODEL_API_KEY`: задайте их явно в `.env` или окружении; наличие defaults у backend `Settings` не заменяет обязательную конфигурацию клиента.

При Docker Compose есть ещё два уровня:

- `.env` используется Compose для подстановок вроде `${DJEDAI_PORT:-8080}` и передаётся backend через `env_file`.
- Блок `environment` в [`compose.yaml`](../compose.yaml) перекрывает значения `.env`: `APP_ENV=production`, SQLite `/app/var/app.db`, каталоги внутри `/app/var`, `CP1_LOCAL_MODE=false`, пустой CORS allowlist. Изменение соответствующих путей в `.env` не переносит данные Docker-установки.

Не используйте обычный `docker compose config` для публикации отчёта: он может раскрыть переменные и пароли. Для проверки синтаксиса достаточно:

```sh
docker compose config --quiet
```

Большая часть настроек кэшируется на время процесса. После изменения `.env` пересоздайте backend; обычный `restart` не перечитывает `env_file` контейнера:

```sh
docker compose up -d --force-recreate --wait --wait-timeout 180 backend
```

Настройки модели, сохранённые через UI/API, читаются для нового хода и построения описаний каталога без перезапуска. Уже выполняющийся вопрос продолжает работать со своим снимком настроек.

## Основные параметры и хранение

| Переменная | Значение по умолчанию вне Compose | Назначение |
| --- | --- | --- |
| `APP_ENV` | `development` | Имя окружения; в Compose `production` |
| `LOG_LEVEL` | `INFO` | Уровень журналирования конфигурации приложения |
| `APP_DATABASE_URL` | `sqlite:///./var/app.db` | Метаданные, пользователи, сессии, каталог, история и настройки |
| `DATASETS_DATA_DIR` | `./var/data/datasets` | Сохранённые CSV, DuckDB и ревизии датасетов |
| `RESULTS_DATA_DIR` | `./var/data/results` | Данные сохранённых вычислений в Parquet |
| `DIAGNOSTICS_DIR` | `./var/diagnostics` | Локальный журнал оператора |
| `SOURCE_ENCRYPTION_KEY` | не задан | Fernet-ключ сохранённых подключений БД и ключа модели из UI |
| `SESSION_SECRET` | встроенное dev-значение | Резерв для будущего подписывания; текущие непрозрачные Bearer-сессии его не используют |

Приложение по умолчанию публикует API с префиксом `/api`; значение версии ответа health задаётся в коде `Settings`. `APP_DATABASE_URL` относится к БД **самого приложения**, а не к PostgreSQL/ClickHouse пользователя. Источники подключаются через UI или [API](api.md) и сохраняются в SQLite как зашифрованные реквизиты. Текущая поставка и эксплуатационные инструкции рассчитаны на SQLite и один backend-процесс; произвольный SQLAlchemy URL не означает проверенную поддержку иной многопроцессной топологии.

### Ключ шифрования

CSV доступен без `SOURCE_ENCRYPTION_KEY`. Для нового сохранённого PostgreSQL/ClickHouse-подключения нужен корректный Fernet-ключ. Он же обязателен, если требуется сохранить `MODEL_API_KEY` через UI. Проверка доступности источника ничего не сохраняет; успешная проверка не гарантирует, что подключение можно сохранить без серверного ключа.

Сгенерировать ключ в уже работающем backend:

```sh
docker compose exec backend /app/.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Сохраните результат в `.env` и отдельном защищённом хранилище, затем пересоздайте backend. Не вставляйте результат в issue, логи или документацию. Замена ключа не выполняет перешифрование существующих записей: старые подключения и сохранённый ключ модели перестают расшифровываться. Потеря ключа делает эти реквизиты невосстановимыми даже при наличии SQLite. Автоматической ротации ключа нет.

Шифрование защищает реквизиты источников, а не весь том. CSV, DuckDB, Parquet, вопросы и ответы содержат пользовательские данные и требуют защиты на уровне хоста и резервных копий. Подробности — в [эксплуатации](operations.md).

## Модель и настройки интерфейса

| Переменная | Образец / default | Назначение |
| --- | --- | --- |
| `MODEL_BASE_URL` | `https://api.deepinfra.com/v1/openai` | Полный базовый HTTP(S) URL OpenAI-совместимого API |
| `MODEL_NAME` | `Qwen/Qwen3.6-35B-A3B` | Идентификатор модели у провайдера |
| `MODEL_API_KEY` | пусто | Ключ сервера модели; для локального API используйте принятое им значение |
| `MODEL_REVISION` | не задан | Фиксация ревизии весов для воспроизводимости локального запуска |
| `MODEL_SETTINGS_FROM_UI` | `false` | Разрешить изменение адреса и ключа через интерфейс/API |
| `MODEL_ALLOWED_NAMES` | пустой список + `MODEL_NAME` | Модели, доступные пользователю при выключенном предыдущем флаге |

Значения адреса и модели выше присутствуют в `.env.example` и backend `Settings`; для клиента они должны фактически присутствовать в окружении/`.env`. `MODEL_REVISION` не загружает веса и не запускает локальную модель. Совместимый модельный сервис запускается и обслуживается отдельно.

Настройки в UI **общие для всей установки**, а не персональные настройки аккаунта. Любой вошедший пользователь может выбрать разрешённую модель; изменение действует на последующие вопросы других пользователей и новые описания каталога.

При `MODEL_SETTINGS_FROM_UI=false` ключ и адрес берутся только из серверной конфигурации. UI предлагает модели из `MODEL_ALLOWED_NAMES`; список принимает CSV или JSON-массив, `MODEL_NAME` включается автоматически. Передача `base_url`/`api_key` в `PUT /api/settings/model` или проверку модели запрещена с 403, модель вне списка — 422. Сохранённая ранее модель, удалённая администратором из списка, больше не применяется.

`MODEL_SETTINGS_FROM_UI=true` предназначен для локального запуска одним пользователем: вошедший пользователь может сохранить произвольный адрес, модель и ключ. Такое разрешение даёт возможность перенаправить будущие данные на другой сервер. В сетевой установке сохраняйте `false`.

Правила обновления:

- Переданное непустое поле перекрывает `.env`; непереданное поле сохраняет прежнюю настройку.
- Пустая строка сбрасывает конкретное поле к `.env`. `null` не является командой удаления.
- Ключ сохраняется в SQLite зашифрованным. Ответ содержит только `api_key_set`/`api_key_from_ui`, сам ключ не возвращается.
- Без Fernet-ключа сохранение ключа модели получает 409. Если существующий шифротекст перестал расшифровываться, чат не подставляет тайно ключ из `.env`: модель считается недоступной. Исправьте серверный ключ или явно сбросьте/замените сохранённый ключ в разрешённом режиме.
- После выключения `MODEL_SETTINGS_FROM_UI` сохранённые адрес и ключ игнорируются; допустимый выбор модели может продолжать применяться.

`POST /api/settings/model/check` проверяет введённые значения поверх сохранённых и `.env`, ничего не сохраняет. Один короткий запрос имеет собственный бюджет 10 с и отключённые SDK-повторы. Результат — `ok`, `not_configured`, `invalid_key`, `unreachable`, `unknown_model` или `model_error`; текст ответа/ошибки провайдера не раскрывается. Успех проверки соединения не проверяет пригодность модели для сложной аналитики.

### Возможности выбранной модели

Reasoning, цены и разрешение полного контекста считаются подтверждёнными только для пары `MODEL_BASE_URL` + `MODEL_NAME` из окружения/`.env`. Смена одного лишь ключа не меняет эту пару. URL сравнивается без завершающих `/`.

Для другой пары, выбранной в UI:

- все стадии используют `provider_default`, без явного `reasoning_effort`;
- расчётная стоимость неизвестна;
- применяется ограниченная политика данных, даже если `ALLOW_DATA_SHARING=true`.

Ограниченная политика всё ещё разрешает значения **текущего** результата. Она исключает примеры каталога и сырые строки прошлых ходов. Возврат к исходной паре восстанавливает связанные настройки. `matches_env` в API сообщает именно о совпадении пары, а не о результатах запроса к провайдеру.

## Время, повторы, контекст и reasoning

| Переменная | Default | Ограничение / смысл |
| --- | --- | --- |
| `AGENT_TURN_TIMEOUT_SECONDS` | `120` | `0 < x <= 600`; общий бюджет принятого вопроса |
| `MODEL_TIMEOUT_SECONDS` | `60` | `0 < x <= 600`; одна HTTP-попытка, дополнительно ограниченная остатком хода |
| `MODEL_MAX_RETRIES` | `1` | Целое `0..3`; дополнительные попытки одного модельного вызова |
| `MODEL_RETRY_DELAY_SECONDS` | `0.5` | `0..10`; начальная экспоненциальная пауза |
| `MODEL_MAX_OUTPUT_TOKENS` | `2048` | Положительное число; меньше `MODEL_CONTEXT_TOKENS` |
| `MODEL_CONTEXT_TOKENS` | `8192` | Положительный бюджет контекста приложения |
| `DASHBOARD_MAX_OUTPUT_TOKENS` | `4096` | Отдельный выходной бюджет плана дашборда, меньше контекста |
| `MODEL_REASONING_SUPPORTED` | `false` | Подтверждена ли поддержка явного reasoning для серверной пары |
| `MODEL_REASONING_UNDERSTAND` | `provider_default` | Настройка стадии understand |
| `MODEL_REASONING_PLAN` | `provider_default` | Настройка стадии plan |
| `MODEL_REASONING_VISUALIZE` | `provider_default` | Настройка стадии visualize |
| `MODEL_REASONING_COMPOSE` | `provider_default` | Настройка стадии compose |
| `MODEL_REASONING_VERIFY` | `provider_default` | Настройка стадии verify |

Для reasoning допустимы `provider_default`, `none`, `low`, `medium`, `high`. `provider_default` не отправляет параметр провайдеру. Любое другое значение требует `MODEL_REASONING_SUPPORTED=true`; приложение не выполняет незаметный fallback после отказа провайдера. Поддержку проверяют для конкретной модели и endpoint, а не для названия провайдера в целом.

SDK-повторы отключены; прикладной клиент повторяет сетевые ошибки/таймауты и HTTP 408, 429, 500, 502, 503, 504. Постоянные ошибки, неверный JSON и нарушение схемы не получают таких повторов. `Retry-After`/`retry-after-ms` учитывается в пределах общего бюджета. Ожидание допуска к чату имеет отдельный лимит; проверки доступа и создание runtime выполняются до бюджета хода. Синхронный сторонний Python-код может возвращаться после закрытия SSE, поэтому увеличение таймаута не заменяет контроль нагрузки. Полное описание — [agent-deadlines.md](agent-deadlines.md).

## Политика отправки данных

`ALLOW_DATA_SHARING=false` по умолчанию. Это не отключение внешнего API: модель получает имена и типы колонок, описания, статистику, вопрос и историю текста, факты/агрегаты и разрешённые значения текущего вычисления. Примеры и top-values каталога, а также сырые строки результатов прежних ходов исключаются. `true` дополнительно разрешает эти категории для доверенной серверной пары модели.

Распознаваемые секреты, DSN, ключи, токены и пароли запрещены в обоих режимах. Политика очищает чувствительные колонки и контекст непосредственно перед вызовом модели. Это программная фильтрация категорий и известных признаков секретов; её нельзя считать универсальной анонимизацией любых персональных данных. Если текущие результаты нельзя передавать внешнему endpoint, настройте допустимый локальный endpoint и сетевую политику организации.

`ALLOWED_OUTBOUND_HOSTS` существует в конфигурации, но не обеспечивает сетевой allowlist. Ограничение исходящего доступа требует внешнего firewall/proxy/сетевого окружения. Подробное принятое решение и категории — [173-data-transfer-policy.md](decisions/173-data-transfer-policy.md).

## Загрузка, очереди и квоты

| Переменная | Default | Что ограничивает |
| --- | --- | --- |
| `MAX_CONCURRENT_CHATS` | `4` | Реально работающие потоки чатов всего процесса |
| `MAX_CONCURRENT_CHATS_PER_OWNER` | `1` | Работающие потоки одного владельца |
| `MAX_QUEUED_CHATS` | `10` | Общая очередь ожидания допуска |
| `MAX_QUEUED_CHATS_PER_OWNER` | `2` | Очередь владельца |
| `CHAT_ADMISSION_TIMEOUT_SECONDS` | `10.0` | Ожидание допуска, секунды, больше нуля |
| `MAX_CONCURRENT_DATASET_JOBS` | `2` | Фоновые задачи датасетов всего процесса |
| `MAX_CONCURRENT_DATASET_JOBS_PER_OWNER` | `1` | Фоновые задачи владельца |
| `MAX_QUEUED_DATASET_JOBS` | `10` | Очередь фоновых задач |
| `MAX_QUEUED_DATASET_JOBS_PER_OWNER` | `2` | Очередь задач владельца |
| `MAX_UPLOAD_REQUEST_BYTES` | `2000000000` | Сумма файлов одной загрузки, 2 ГБ в десятичных байтах |
| `MAX_OWNER_STORAGE_BYTES` | `5000000000` | Проверка текущего дискового объёма датасетов владельца при приёме CSV |

Параллелизм положительный; очереди могут быть нулевыми. Лимиты параллелизма владельца не должны превышать глобальные, а размеры удовлетворяют `request <= owner`. Отдельный лимит CSV-файла удалён: один файл ограничен общим бюджетом запроса. `MAX_UPLOAD_FILE_BYTES` больше не применяется. Числа размера — десятичные байты, не MiB.

Владельцы обслуживаются по кругу. В одном чате одновременно работает один ход; повторная отправка во время `running` получает 409. Очередь/ожидание допуска ограничены и возвращают 429 при отказе. Слот удерживается до фактического выхода worker, в том числе после отмены или deadline.

Потоковый middleware проверяет общий HTTP-body загрузки до multipart-парсинга с запасом 64 KiB на оформление multipart. Далее сервис отдельно считает суммарные байты файлов. nginx имеет независимый внешний порог `2100m`. Увеличение только backend-лимита не изменяет порог nginx. Нехватка места во временном каталоге или при сохранении возвращает 507 `insufficient_storage`; безопасный multipart-парсер закрывает временные файлы, а сервис удаляет неполный каталог датасета. Место требуется одновременно во временном каталоге и в постоянном хранилище; см. [инфраструктуру](../infra/README.md#место-на-диске-для-загрузки-csv).

Квота учитывает фактические файлы датасетов владельца и одновременно резервируемые байты CSV. Это не общий лимит тома: результаты Parquet и диагностика находятся в других каталогах, а будущий рост DuckDB при профилировании и загрузка ClickHouse не резервируются этой же проверкой CSV. Следите за свободным местом независимо от квоты. Очередь чатов и очередь датасетов не являются общим admission-контроллером всех маршрутов: например, автономный refresh дашборда имеет собственную логику.

Механизмы находятся внутри одного процесса. Не запускайте несколько Uvicorn workers или несколько backend-контейнеров на одном томе, рассчитывая на суммарное соблюдение этих лимитов. Решение и тестовые сценарии — [172-concurrency-queues-upload.md](decisions/172-concurrency-queues-upload.md).

| `CATALOG_MAX_AGE_HOURS` | `24` | Возраст профиля живого PostgreSQL для предупреждения |
| `CATALOG_DESCRIPTIONS` | `false` в коде, `true` в образце | Модельные русские описания нового каталога |
| `CLICKHOUSE_MAX_ROWS` | `10000000` | Общий порог строк импортируемых таблиц |

| `CLICKHOUSE_QUERY_TIMEOUT_SECONDS` | `300` | Таймаут ClickHouse, целое `1..3600` |

Сбой модельного описания добавляет предупреждение, статистический каталог остаётся доступен. Изменение описаний/typing/порогов не переписывает старый каталог само по себе: запускайте явное обновление датасета. PostgreSQL читается как живой read-only источник, ClickHouse копируется в локальный DuckDB; эти режимы имеют разную семантику актуальности. См. [данные и каталог](data-and-catalog.md) и [аналитику](analytics.md).

| `AUTH_RATE_LIMIT_WINDOW_SECONDS` | `300` | Фиксированное окно лимита, секунды |
| `BACKEND_CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Явные dev-origins; пусто запрещает все, `*` отклоняется |
| `CP1_LOCAL_MODE` | `false` | Только legacy bootstrap локального владельца; не bypass авторизации |
| `CP1_LOCAL_USER_ID` | `cp1-local-user` | ID legacy владельца для bootstrap |
| `DJEDAI_PORT` | `8080` в Compose | Loopback-порт nginx на хосте |
| `VITE_API_BASE_URL` | `/api` в поставке | Публичный базовый путь API frontend |

Сессия действует 86400 с и отзывается logout текущего токена. Это параметры реализации, не переменные `.env`. Для auth-body отдельно действуют 16 KiB и 10 с, одновременно допускается до четырёх операций login/register на процесс. Ограничения и очереди в памяти сбрасываются после перезапуска.

`VITE_*` — публичные значения сборки: не храните там ключи, DSN и пароли. Compose задаёт frontend `/api` и выключенные mocks при сборке; редактирование `VITE_*` в backend `.env` не перенастраивает собранный nginx bundle. Vite dev-прокси и MSW описаны в [frontend.md](frontend.md).

Backend не публикует порт на хост; nginx публикуется на `127.0.0.1`. Он передаёт Bearer и заменяет входящий `X-Forwarded-For` реальным адресом клиента. Доверие Uvicorn к forwarded headers допустимо только при сохранении этой закрытой топологии. TLS, публичный hostname и полноценная внешняя поставка в основном Compose не настроены.

## Диагностика и цены

| Переменная | Default | Назначение |
| --- | --- | --- |
| `DIAGNOSTICS_MAX_BYTES` | `10000000` | Порог ротации JSONL, минимум 1024 |
| `DIAGNOSTICS_BACKUPS` | `5` | Количество архивов, `1..100` |
| `MODEL_INPUT_PRICE_PER_MILLION_USD` | не задан | Неотрицательная цена миллиона входных токенов |
| `MODEL_OUTPUT_PRICE_PER_MILLION_USD` | не задан | Неотрицательная цена миллиона выходных токенов |
| `MODEL_PRICE_REFERENCE` | не задан | Дата, provider/model/tier и источник ставки |

Все три поля тарифа задаются вместе. Нулевой тариф допустим, неизвестная цена не заменяется нулём. Оценка основывается только на сообщённом usage и не является счётом провайдера; `actual_charge_usd` неизвестен. Тариф не переносится на другую пару модели из UI. Чтение журнала и границы данных — [agent-diagnostics.md](agent-diagnostics.md).

## Необязательные demo и test-параметры

`DEMO_PG_ADMIN_PASSWORD`, `DEMO_PG_LOADER_PASSWORD`, `DEMO_PG_READER_PASSWORD`, `DEMO_CH_ADMIN_PASSWORD`, `DEMO_CH_LOADER_PASSWORD`, `DEMO_CH_READER_PASSWORD` нужны только профилю Compose `demo`. Пароли задаются локально; роли создаются при первом запуске пустых томов. `DEMO_PG_PORT=55432`, `DEMO_CH_HTTP_PORT=58123` управляют loopback-портами демо-БД.

`DJEDAI_DEMO_PG_LOADER_DSN`, `DJEDAI_DEMO_PG_READER_DSN`, `DJEDAI_DEMO_CH_LOADER_URL`, `DJEDAI_DEMO_CH_READER_URL` читают seed/verify-скрипты, а не backend. `DJEDAI_TEST_PG_DSN`, `DJEDAI_TEST_CH_URL` относятся к интеграционным тестам. Полные команды и различие адресов хоста/контейнера — [local-build.md](local-build.md) и [infra/README.md](../infra/README.md).

Границы реализованных механизмов проверяют [тесты настроек модели](../tests/unit/backend/test_model_settings.py), [допуска](../tests/unit/backend/test_admission.py), [параллельных задач датасетов](../tests/unit/backend/test_dataset_concurrency.py), [шифрования](../tests/unit/backend/test_source_secrets.py) и [политики на модельном транспорте](../tests/unit/agent/test_data_policy_transport.py). Они используют управляемые сценарии, а не подтверждают любой внешний endpoint и объём данных.

При изменении конфигурации ориентируйтесь на действующие поля и проверки кода, а при оценке качества — на [проверки проекта](quality.md). Успешная загрузка settings или health не подтверждает доступ к модели, read-only права источника и правильность ответа.
