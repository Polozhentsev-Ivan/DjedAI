# Документация разработчика

Для участников команды, которые разбираются в устройстве DjedAI, меняют код или интегрируют приложение с другой системой. Предполагаются базовые знания Python, TypeScript, HTTP и Git.

## Начать работу

1. [Обзор проекта](overview.md) — назначение системы, понятия и границы.
2. [Архитектура](architecture.md) — компоненты, потоки данных и принятые решения.
3. [Окружение разработчика](development.md) — зависимости, запуск из исходников и изменение контрактов.
4. [GitHub и рабочий процесс](project-workflow.md) — задачи, ветки, ревью и CI.

## Справочники и решения

[Подробные контракты, решения и исторические материалы](reference.md) дополняют главы выше. К ним обращаются при работе с конкретным изменением.

Установку сервиса, резервирование и восстановление описывает отдельное [руководство администратора](../administrator/README.md). Поведение интерфейса с точки зрения конечного пользователя — отдельное [руководство пользователя](../user/user-guide.md).

## Как обновлять документацию

Меняйте описание вместе с поведением компонента. В технических главах фиксируйте контракт, причины решения и ограничения. Пользовательские действия обновляйте в пользовательском руководстве, параметры развёртывания — в административном. Исторические протоколы сохраняют дату и версию проверенного кода.
