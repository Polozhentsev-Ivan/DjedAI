# Рендерер ChartSpec — #87

`ResultChart` читает `/api/results/{spec.result_id}/data` общим клиентом с Bearer-сессией.
`SpecChart` отображает результат через ECharts либо существующие React-компоненты.
Цвета, шрифты, границы и размеры берутся из `frontend/src/styles`; переключение темы,
resize и освобождение экземпляра ECharts остаются общими для всех графиков.
Блок графика в чате использует существующий `ChartCard`, таблица — `DataTable`.

Схема `ChartSpec` и HTTP API не меняются. Ниже описано соответствие её существующих
полей строкам сохранённого результата. Это вход рендерера для производителя
спецификаций #75 и будущих виджетов #97; генерация этих результатов и выбор типа
агентом не входят в #87.

| Тип | Поля спецификации | Одна строка результата |
| --- | --- | --- |
| line / area / bar | `x` — категория, дата или число; `y` — меры | Значения X и мер; `null` остаётся пропуском |
| pie | `x` — категория; одна мера `y` | Название и неотрицательное значение |
| scatter | `x` — числовая колонка; `y` — числовые меры | Готовая пара X/Y; неполная пара не рисуется |
| histogram | `x` — подпись готового интервала; одна мера `y` — частота | Интервал и рассчитанная backend частота; порядок интервалов приходит от backend |
| heatmap | `x` и `color` — две категории; одна мера `y` | Единственный готовый агрегат на пару категорий |
| box | `x` — категория; **пять мер `y` в порядке нижний ус, Q1, медиана, Q3, верхний ус** | Пять готовых статистик в одной единице; порядок значений проверяется |
| table | `x`, затем меры `y`, затем `color`; без этих полей — все колонки | Проекция исходной строки; подписи из spec или дескрипторов API |
| kpi | Одна мера `y` | Полный результат строго с одной строкой; `null` отображается как «—» |

Гистограмма получает готовые интервалы сопоставимой ширины: вычислять границы,
частоты или плотность по сырым значениям браузер не будет. Box plot получает готовые
усы и квартили: рендерер не выбирает метод расчёта, не пересчитывает их и не выводит
новые выбросы. Разные правила расчёта должны быть описаны в subtitle/происхождении
сохранённого результата. Сырые значения вместо пяти статистик дают видимую ошибку.
Точки выбросов можно показать отдельной scatter-спецификацией.

`color` разбивает готовые строки line/area/bar/scatter на ряды, а для heatmap задаёт
вторую категорию. Scatter выделяет группы по исходным значениям: `null` и строка
`"Нет значения"`, число `1` и строка `"1"` остаются разными группами. При совпадении
подписей легенда и подсказки уточняют тип значения; каждый ряд переключается отдельно.
Повторы пары X/группа в агрегированных графиках отклоняются:
сложение и другие агрегаты выполняет backend. Для pie/histogram/box/kpi нужны
отдельные результаты групп; неподдержанная цветовая разбивка вызывает объяснимую
ошибку. `orientation` используется для bar и box; `stacked` — для line/area/bar.
Аннотации line/area/bar привязаны к исходному X и существующему значению меры;
отсутствующие точки не дорисовываются. Числовая ось scatter не превращается в
категориальную.

`sort` стабильно сортирует **полученные** строки перед `limit`, не меняя сохранённые
данные. Без `limit` показывается весь результат, но не больше 2000 строк: больше браузеру
не отрисовать без задержек. Числа сравниваются как числа, пропуски идут последними.
Ограничение или `truncated=true` сопровождается заметкой о неполном отображении;
это не глобальный top-N по недоступной части результата. Легенда pie показывает
исходное значение в формате меры, включая уже рассчитанные проценты, и не вычисляет
долю от обрезанной выборки. Формат `percent` ожидает готовые значения 0–100,
`money` следует текущему оформлению ₽/млн ₽, `int` — целое число; `number` сохраняет
десятичную часть. Отображение не изменяет исходные числовые данные.

Все типы показывают общий пустой результат, ошибки получения/несовместимой формы
данных и явный повтор GET при ошибке API. Пропуски не подменяются нулями, KPI не
агрегирует несколько строк. Строковые и объектные дескрипторы колонок поддерживаются.
Всплывающие HTML-подсказки экранируют названия из данных и спецификации.

## Проверка

Десять ручных примеров находятся в
`frontend/src/fixtures/charts.ts`; рабочий UI их не импортирует. Набор
`frontend/e2e/charts.spec.ts` подаёт их через управляемые HTTP-ответы в **production
чат**, использует настоящий ECharts/SVG, переключает тему, меняет ширину, проверяет
ошибку/повтор GET и повторное открытие. Модель и GPU не нужны.

Из `frontend/`:

```sh
npm run test -- src/charts
npm run test:e2e -- charts.spec.ts
```

Скриншоты каждого типа и дополнительных состояний сохраняются в Playwright output.
Для вывода за пределами репозитория задайте `DJEDAI_E2E_OUTPUT` абсолютным путём;
CI использует runner temp и публикует их в `cp1-browser-evidence`.
