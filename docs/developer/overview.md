# Обзор проекта

DjedAI помогает исследовать незнакомые данные с помощью вопросов на русском языке. Пользователь выбирает источник, изучает структуру таблиц, задаёт вопрос, получает расчёт и объяснение, затем уточняет запрос или сохраняет полезные представления в дашборд.

Основные пользователи — аналитики и руководители. Человеку не обязательно заранее знать физические имена колонок или писать SQL для каждого вопроса. При этом приложение сохраняет происхождение ответа: инструмент, аргументы, SQL, версию источника и доступные результаты.

## Принцип работы

Модель понимает вопрос, предлагает план и объясняет результат. Вычисления выполняются зарегистрированными инструментами по выбранному датасету. Каталог связывает слова пользователя с таблицами и полями, подтверждённые определения метрик фиксируют бизнес-смысл расчёта.

Неоднозначную метрику нужно уточнить; пропуски и неразобранные значения могут ограничивать вывод. У текста есть этап проверки, но это не гарантия правильности любого ответа. Условия применения методов и независимая проверка описаны в [аналитике](analytics.md) и [качестве](quality.md).

## Возможности

| Задача | Что предоставляет приложение |
| --- | --- |
| Познакомиться с источником | Несколько CSV, read-only PostgreSQL, ограниченный локальный снимок ClickHouse. |
| Понять структуру и качество | Типы, пропуски, статистики, преобразования, связи, описания и свежесть каталога. |
| Получить ответ | Вопрос, уточнение, текст, таблица и график по доступным данным. |
| Продолжить анализ | Контекст чата, прежние результаты, изменение фильтра или вида представления в поддерживаемом сценарии. |
| Применить аналитику | SQL, частоты, временные агрегаты, дубли/аномалии, сезонность/сегменты, корреляции/лаги, прогноз и подтверждённые метрики. |
| Сохранить представления | Dashboard с воспроизводимыми расчётами, чтением snapshot и отдельным refresh. |
| Вернуться к работе | Собственные datasets/chats/results/dashboards после повторного входа и restart. |

Точные действия и границы UI — в [руководстве пользователя](../user/user-guide.md). Реализованный API может иметь дополнительную операцию, для которой нет отдельного элемента интерфейса; такие случаи отмечаются явно.

## Основные понятия

| Понятие | Значение |
| --- | --- |
| Датасет | Аналитический контекст пользователя с одной или несколькими таблицами и общим каталогом. |
| Источник | CSV или подключённая БД. PostgreSQL читается как живой источник; ClickHouse здесь материализуется в ограниченный snapshot. |
| Каталог | Структура, типы, статистики, связи, описания, преобразования и ревизия профиля. |
| Чат | Диалог, связанный с датасетом и владельцем; вопросы, исходы ходов, ответы и ссылки на расчёты. |
| ToolResult | Данные, факты, статус, параметры и происхождение одного вычисления, включая empty/error. |
| Метрика | Версия подтверждённого бизнес-определения: формула, популяция, связи, единицы. |
| Dashboard | Сохранённые виджеты с воспроизводимыми определениями расчёта. |
| Refresh | Новый пересчёт определения с новыми результатами; чтение сохранённого снимка само по себе не пересчитывает данные. |

## Где исполняется приложение

Основная установка — один backend и browser frontend, собранные Compose. Backend хранит метаданные в SQLite, datasets в DuckDB/CSV, результаты в Parquet, диагностику в JSONL. Внешние источники и модель подключаются по сети.

Профиль по умолчанию использует внешний DeepInfra endpoint и Qwen/Qwen3.6-35B-A3B. Поддерживается настройка совместимого API. «Локальная платформа» обозначает место UI, backend и основных хранилищ; разрешённый контекст отправляется внешней модели. [Политика данных](../decisions/173-data-transfer-policy.md) описывает состав передачи.

Ключ/адрес API на сетевой установке задаёт оператор. В интерфейсе выбираются разрешённые модели; возможность менять credential/address включается серверной настройкой для подходящего локального сценария. Настройки общие для установки, а не персональный провайдер каждого аккаунта.

## Как оценивать ответ

1. Проверьте выбранный датасет и смысл метрики.
2. Откройте результат и «Как посчитано»: фильтры, SQL, единицы и происхождение.
3. Учтите предупреждения о типизации, данных и свежести.
4. Для значимого решения сравните число с независимым контрольным расчётом.

Корреляция не доказывает причинность. Прогноз зависит от истории и метода, интервал — от принятых допущений. Ошибка и пустая выборка не являются нулевым значением показателя.
