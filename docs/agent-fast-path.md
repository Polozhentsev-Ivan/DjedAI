# Быстрый маршрут для точного COUNT и структуры

Вопросы этого раздела обслуживаются без вызова модели: `load_ctx → fast_route`,
затем `execute → fast_compose → cite_metrics` для числа строк или
`fast_compose` для структуры. Остальные вопросы проходят прежний маршрут
`understand → plan → execute → visualize → compose → verify` и не меняют смысл
из-за эвристики.

## Поддерживаемые вопросы

Распознавание требует полного совпадения с шаблоном. Регистр, лишние пробелы,
завершающая пунктуация и вежливое «пожалуйста»/«please» в конце не важны.
Имя таблицы можно не указывать только в датасете с единственной таблицей.

**Число строк всей таблицы:**

- `Сколько строк?`
- `Сколько всего строк?`
- `Сколько записей?`
- `Сколько строк в <таблица>?`
- `Сколько всего строк в таблице <таблица>?`
- `Сколько записей в таблице <таблица>?`
- `Какое количество строк в таблице <таблица>?`
- `Каково количество строк в таблице <таблица>?`
- `Число строк в таблице <таблица>?`
- `How many rows in table <table>?`
- `How many rows are in the table <table>?`
- `What is the row count of table <table>?`

**Структура таблицы:**

- `Покажи структуру таблицы <таблица>?`
- `Покажи схему таблицы <таблица>?`
- `Структура таблицы <таблица>?`
- `Какова структура таблицы <таблица>?`
- `Опиши структуру таблицы <таблица>?`
- `Опиши таблицу <таблица>?`
- `Какие колонки в таблице <таблица>?`
- `Какие столбцы/поля в <таблица>?`
- `Show structure of table <table>?`
- `What columns are in table <table>?`
- `Describe table <table>?`

`<таблица>` — `table_id` из текущего каталога или его `original_name`.
Совпадение ищется без учёта регистра; кавычки вокруг имени (`"..."`, `«...»`, `‘...’`)
допустимы. Одинаковое имя у нескольких таблиц считается неоднозначным.
Слова `table`/`таблица` и пробелы внутри имени в кавычках сохраняются:
`«table orders.csv»` и `«orders.csv»`, а также `«a  b.csv»` и `«a b.csv»`
обозначают разные имена. Служебные слова распознаются только целиком.
Для имени без кавычек сначала проверяется полное совпадение с каталогом:
`Сколько строк в таблице table orders.csv?` выбирает `table orders.csv`,
даже если рядом есть `orders.csv`. Только неизвестный префикс `table`/`таблица`
может быть снят как часть формулировки. Неоднозначное точное имя и неизвестное
имя в кавычках не заменяются более коротким именем.
Само слово `table`/`таблица` без кавычек по-прежнему означает отсутствие имени;
для буквального выбора таблицы с таким именем нужны кавычки.

## Что остаётся обычному агенту

Быстрый маршрут не срабатывает, если в вопросе есть что-то кроме точного
COUNT всей таблицы или запроса структуры. В частности:

- фильтры, даты, условия `WHERE`, слова «после», «до», «исключая», «не»;
- JOIN, объединение таблиц, несколько таблиц через «и»;
- группировки, разрезы, «по датам», «по месяцам», «по категориям»;
- `COUNT(DISTINCT)`, «уникальных», «различных»;
- ссылки на прошлый ответ, «в прошлом результате», «теперь», изменение метрики;
- любое дополнительное указание («включая дубли», «в валюте», «с аномалиями»).

Неизвестная таблица, отсутствующий/чужой каталог или несколько таблиц без
явного выбора также не включают быстрый маршрут: вопрос уходит в общий граф,
где модель может уточнить формулировку.

## Число строк: расчёт и провенанс

`fast_route` строит `run_sql` с одним запросом
`SELECT COUNT(*) AS row_count FROM "<table_id>"`. Таблица уже разрешена по
каталогу датасета чата, а выполнение идёт обычным защищённым путём:

- `tool_dispatcher` backend передаёт `allowed_tables` текущего owner/dataset;
- SQL проходит общий read-only и dataset-scope gate;
- результат сохраняется через штатное сохранение `ToolResult` с `result_id`,
  SQL, параметрами, временем и ревизией чтения;
- `result_id` попадает в `result_ids` сообщения и в фокус следующего хода.

Число берётся из ячейки сохранённого результата, а не из текста вопроса и не из
`row_count` каталога. `0` — корректный ответ. `NULL`, пустой результат и ошибка
инструмента не превращаются в ноль: пользователь получает явную ошибку, а
неподтверждённый ответ не публикуется. Каталожный `row_count` для внешней БД
может быть устаревшим, поэтому в ответе на COUNT он не используется.

## Структура: текущий каталог

`fast_compose` строит структуру из `DatasetCatalog`, загруженного для датасета
этого чата: имя таблицы, колонки, типы, роли, ключи, уникальность, пропуски и
описания. `row_count` профиля в ответ не подставляется как свежий COUNT.
Если каталог недоступен или таблица исчезла из него, возвращается явная ошибка.
Для структуры блок «Как посчитано» не добавляется и прошлые результаты не
используются.

## Изоляция и кэш

Отдельного кэша нет. Каждый ход заново загружает каталог, привязанный backend к
owner/dataset, а `load_ctx` очищает `fast_path`, результаты и ответ предыдущего
хода. Поэтому смена датасета или аккаунта не может переиспользовать число,
таблицу или структуру другого контекста. `run_sql` выполняется в соединении и
scope текущего датасета; сохранённый результат проверяется по owner/chat/dataset
при чтении истории.

## Наблюдаемость

В диагностике быстрый ход виден как стадии `fast_route`, `execute` и
`fast_compose`; существующий узел `cite_metrics` добавляет провенанс COUNT.
Событие `fast_path_selected` содержит только
`kind` и `table_id`, без текста вопроса. `run_finished.duration_ms` — общее время
хода; `stage_finished.duration_ms` — время каждой стадии. При быстром маршруте
событий `model_call_started`/`model_call_finished` нет.

## Проверка

```sh
uv run --locked pytest --strict-markers tests/unit/agent/test_fast_path.py \
  tests/unit/agent/test_graph.py -q
uv run --locked pytest --strict-markers \
  tests/integration/test_cp1_runtime.py::test_fast_path_count_and_structure_skip_model_and_survive_reload -q
```

Тесты проверяют точное число, включая `0`, `NULL` и ошибку инструмента,
структуру без `row_count` каталога, отрицательные примеры, неоднозначный выбор
таблицы, отсутствие вызовов модели, сохранение `result_id` после перезагрузки и
изоляцию двух датасетов.
