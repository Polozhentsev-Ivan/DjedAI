## Как воспроизвести и записать результат

1. Выбрать проверяемый коммит, записать `git rev-parse HEAD`, запустить production
   Compose по [README](README.md). Зафиксировать ID модели, endpoint без ключа,
   reasoning, таймауты, повторы и лимит контекста из реально применённой конфигурации.
2. Проверить размер и SHA-256 каждого CSV по manifest. Через интерфейс загрузить
   исходный файл, дождаться готовности каталога, создать отдельный чат и выбрать
   нужный датасет. Не добавлять эталон или подсказку с SQL к вопросу.
3. Записать видео: выбранный источник, полный вопрос из таблицы, ожидание ответа,
   итоговый текст/таблицу, единицы и «Как посчитано». Время измерять до готового
   ответа, а не до первого SSE-статуса. Ошибку или таймаут также сохранить в протоколе.
4. Сверить каждую группу и число с YAML, проверить фильтры, знаменатели и понятность
   объяснения. Для #243 выполнить три последовательных запуска каждого вопроса
   в новых чатах; записать все 18 исходов и проверить требование 120 с на ответ.
   Таймаут хода 400 с в профиле модели сам по себе этому требованию не соответствует.
5. Выложить шесть видео в облако; для каждого указать URL, SHA приложения, дату,
   модель, результат, длительность и ссылку на полный протокол повторов.
   Проверить ссылки в чужом браузере без входа, не публикуя ключи, токены и чужие данные.

Числовую часть можно дополнительно проверить без браузера. После настройки окружения
пример для вопроса 6, команды из корня репозитория:

```sh
uv sync --locked
uv run --locked python -X utf8 scripts/eval_runner.py --questions eval/organizer_questions.yaml --manifest eval/datasets/organizer/q6.json --data-file "artifacts/hk-datasets/08_Фоновые_задания.csv" --workers 1 --output artifacts/submission/q6-run1.json
```

Для остальных вопросов заменить manifest, путь к CSV и имя отчёта согласно таблице.
В одном таком отчёте вопросы других датасетов получают `skipped`, поэтому нельзя
считать его проверкой всех шести вопросов. Проверить у нужного `id` статус,
`automated_status`, ошибки, текст ответа, единицы и все `answer_rows`.
`needs_review` требует смысловой оценки; успешное завершение процесса само по себе
не означает правильного ответа. Полный порядок оценки — в [eval/README.md](eval/README.md).
