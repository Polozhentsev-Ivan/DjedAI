# DjedAI

Локальная аналитическая платформа: пользователь загружает CSV или подключает PostgreSQL/ClickHouse, задаёт вопросы на русском языке и получает ответы, графики и сохраняемые дашборды. Агент выполняет расчёты через инструменты; исходные данные и результаты вычислений сохраняются.

В основной ветке доступны CSV, PostgreSQL/ClickHouse, каталог со связями и описаниями, регистрация и личные данные, чат с памятью, аналитические инструменты, графики и дашборды. Production UI и API собираются и запускаются через Docker Compose. Наличие компонентов не заменяет итоговую проверку качества и приёмку пользовательских сценариев.

**Для первого запуска:** [пошаговая инструкция локальной сборки](docs/local-build.md) — Windows и Linux/macOS, настройка модели, проверочный CSV, сохранность данных, необязательные демо-БД и устранение ошибок. На хосте достаточно Git и Docker; Python/Node собираются в контейнерах.

## С чего начать

1. Прочитать [соглашение команды](CONTRIBUTING.md).
2. Посмотреть [руководство по структуре и служебным файлам](docs/repository-guide.md).
3. Изучить [техническую спецификацию](docs/specification.md) и [пояснения к исходным материалам](docs/README.md).
4. Выбрать [issue](https://github.com/Polozhentsev-Ivan/DjedAI/issues), назначить себя исполнителем и создать ветку от актуальной `main`.

```sh
git switch main
git pull --ff-only
git switch -c feat/53-csv-import
```

Участники с доступом на запись могут работать в ветках общего репозитория. При работе через fork PR также направляется в `main` исходного репозитория. Объединение — после ревью по соглашению команды.

## Карта проекта

```text
.github/                  шаблон pull request и CI
docs/                     спецификация, план, руководство и макет интерфейса
frontend/                 браузерное приложение React + TypeScript
src/djedai/
  contracts/              общие форматы данных
  data/                   загрузка, каталог, профилирование, адаптеры
  analytics/              SQL и аналитические инструменты
  agent/                  граф и логика агента
  backend/                API, хранение, авторизация
prompts/                  версионируемые промпты
tests/
  unit/                   проверки отдельных компонентов
  integration/            проверки взаимодействия компонентов
  e2e/                    сквозные пользовательские сценарии
  fixtures/               небольшие общие тестовые данные
eval/                     эталонные вопросы и оценка агента
infra/                    конфигурация локального запуска
scripts/                  вспомогательные команды проекта
```

Python-код находится в `src/djedai/`, браузерный UI — в [frontend/](frontend/README.md) и взаимодействует с сервером только через HTTP API/SSE. Это карта компонентов согласованной архитектуры. README в каталогах описывают границы; реализация, интерфейсы и общие модели добавляются по issues.

Для разбора задержек и ошибок чата есть [журнал диагностики агента](docs/agent-diagnostics.md): этапы, отдельные сетевые попытки, usage и неуспешные ходы сохраняются в постоянном томе Compose.

## Локальная сборка и запуск

Полная процедура: [docs/local-build.md](docs/local-build.md). Для первого запуска нужны Git, Docker с Linux engine и Compose v2, браузер и ключ OpenAI-совместимого API модели. Python/uv и Node/npm устанавливаются внутри образов.

1. Создайте `.env` из [.env.example](.env.example), сохранив существующий локальный файл.
2. Впишите `MODEL_API_KEY`; при другом провайдере согласуйте `MODEL_BASE_URL` и `MODEL_NAME`.
3. Из корня репозитория выполните:

```sh
docker compose config --quiet
docker compose up --build -d --wait --wait-timeout 180
```

Откройте [http://localhost:8080](http://localhost:8080), зарегистрируйтесь и войдите. Настройка модели из UI, проверочный CSV, перезапуск без потери данных, ключ шифрования подключений и демо-БД — в [пошаговом руководстве](docs/local-build.md). Для просмотра состояния используйте `docker compose ps` и `docker compose logs --tail 100 backend frontend`.

[infra/README.md](infra/README.md) описывает контейнеры, proxy и модельные настройки; [agent-deadlines.md](docs/agent-deadlines.md) — время выполнения, повторы и отмену. Разработка frontend отдельно от Compose описана ниже.

## Интерфейс

```sh
fnm use          # Node из .nvmrc; можно nvm use
cd frontend
npm ci
npm run dev      # http://localhost:5173, proxy /api на backend
```

Для демонстрационного mock-API задайте `VITE_API_MOCKS=true` в `frontend/.env.local`; по умолчанию запросы идут к backend. Сценарии mock-API, работа с настоящим backend, команды проверок и устройство приложения описаны в [frontend/README.md](frontend/README.md).

## Разработка и качество

Python-окружением управляем через uv: `uv sync --locked`, команды — через `uv run --locked …`. Прямые зависимости фиксируем через `==`, полный набор — в `uv.lock`. Frontend использует Vite и npm с точными версиями и `package-lock.json`. Минимум покрытия — 80% строк собственного Python-кода и отдельно 80% строк собственного TS/TSX-кода frontend; дополнительно обязательны содержательные проверки критичных сценариев. Правила коммитов, PR, тестирования и ревью описаны в [CONTRIBUTING.md](CONTRIBUTING.md).
