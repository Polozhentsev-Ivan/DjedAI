# DjedAI

Локальная аналитическая платформа: пользователь загружает CSV или подключает PostgreSQL/ClickHouse, задаёт вопросы на русском языке и получает ответы, графики и сохраняемые дашборды. Агент выполняет расчёты через инструменты; исходные данные и результаты вычислений сохраняются.

**Текущий статус: подготовлен только каркас репозитория.** Приложение, Python-окружение, зависимости, контейнеры и CI ещё не реализованы. Команды запуска появятся вместе с соответствующими задачами.

## С чего начать

1. Прочитать [соглашение команды](CONTRIBUTING.md).
2. Посмотреть [руководство по структуре и служебным файлам](docs/repository-guide.md).
3. Изучить [техническую спецификацию](docs/specification.md) и [пояснения к исходным материалам](docs/README.md).
4. Выбрать [issue](https://github.com/Polozhentsev-Ivan/DjedAI/issues), назначить себя исполнителем и создать ветку от актуальной `main`.

```sh
git switch main
git pull --ff-only
git switch -c feat/53-csv-import
```

Участники с доступом на запись могут работать в ветках общего репозитория. При работе через fork PR также направляется в `main` исходного репозитория. Объединение — после ревью по соглашению команды.

## Карта проекта

```text
.github/                  шаблон pull request
docs/                     спецификация, план и руководство
src/djedai/
  contracts/              общие форматы данных
  data/                   загрузка, каталог, профилирование, адаптеры
  analytics/              SQL и аналитические инструменты
  agent/                  граф и логика агента
  backend/                API, хранение, авторизация
  ui/                     пользовательский интерфейс
prompts/                  версионируемые промпты
tests/
  unit/                   проверки отдельных компонентов
  integration/            проверки взаимодействия компонентов
  e2e/                    сквозные пользовательские сценарии
  fixtures/               небольшие общие тестовые данные
eval/                     эталонные вопросы и оценка агента
infra/                    конфигурация локального запуска
scripts/                  вспомогательные команды проекта
```

Это карта компонентов согласованной архитектуры. README в каталогах описывают границы; реализация, интерфейсы и общие модели добавляются по issues.

## Локальная конфигурация

Безопасный образец — [.env.example](.env.example). Для локальных значений создайте `.env`:

```powershell
Copy-Item .env.example .env
```

В Linux/macOS: `cp .env.example .env`. Файл `.env` исключён из Git.

Сейчас образец не читается приложением: механизма загрузки конфигурации ещё нет. Пустые параметры заполняются после согласования БД, модели, сессий и лимитов. Само наличие `.env` не запускает систему.

## Разработка и качество

Python-окружение будет управляться через uv. Прямые зависимости фиксируются через `==`, полный набор — в `uv.lock`; файлы окружения появятся после согласования версий. Минимум покрытия — 80% строк собственного Python-кода, дополнительно обязательны содержательные проверки критичных сценариев. Правила коммитов, PR, тестирования и ревью описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

Даты контрольных точек: **19 октября, 26 октября и 30 октября 2026 года**. Этапы и критерии конкретной работы смотрим в соответствующей issue.
